Parallel Flash: 4 PCBs with Single Lauterbach Trace32 + Single Power Supply

Project: RH_i460 Full Automation Fixture  |  Author: csingh  |  Date: 2026-06-17  |  Rev: 1.0
CHALLENGE ANALYSIS & IMPLEMENTATION GUIDE
1 Executive Summary

The challenge is to flash firmware into 4 PCBs simultaneously placed in the 4-slot automation fixture, using only one Lauterbach Trace32 PowerDebug E40 and one KIKUSUI PWR401L power supply, without investing in 4× instrument sets at this stage.

True simultaneous JTAG/SWD flashing of 4 boards from a single probe is not possible — JTAG is a single-master bus. The recommended solution is sequential flashing via a 4-channel JTAG/SWD hardware multiplexer, with all 4 PCBs powered from the single PSU through per-slot relay isolation. This keeps all 4 PCBs mechanically loaded in the fixture (no robot intervention during flash) while the software cycles through each slot.

Key insight: "Parallel" at the fixture level means all 4 boards are physically loaded and powered at once. Flash is sequential per slot (via MUX), but FCT functional tests run in parallel after all boards are flashed. Cycle-time impact of sequential flash is offset by eliminating 4 individual load/unload robot cycles.

3 Blocking Points, Root Causes & Solutions
#Blocking PointSeverityRoot CauseSolutionOwner
B1 JTAG Bus Contention
Multiple PCBs cannot share SWD/JTAG simultaneously — TDO lines short-circuit each other		 CRITICAL SWD is point-to-point; JTAG daisy-chain requires all targets to forward the chain — any unpowered target breaks the chain Install a 4-channel JTAG/SWD hardware MUX between Trace32 DC20A output and the 4 pogo-pin slots. Only the selected slot's SWD lines are electrically connected; all others are tri-stated. HW Eng
B2 PSU Current Insufficient
PWR401L rated 40V/1A — each RH_i460 PCB may draw 200–500mA; 4 boards = up to 2A		 CRITICAL Single 1A PSU cannot sustain 4 active boards simultaneously, causing voltage droop, false resets, and flash corruption Option A (recommended): Power only the board being flashed (relay closes for active slot, others remain powered-off during flash). After all flashed, power all 4 for FCT.
Option B: Replace PSU with 4A-capable unit (e.g. KIKUSUI PWR802L or equivalent).		 HW Eng
B3 MUX Signal Integrity
JTAG MUX introduces capacitance; high-speed signals can degrade causing flash verify errors		 HIGH Parasitic C of MUX switches and long pogo-pin traces form an RC low-pass filter, limiting max JTAG clock frequency Reduce Trace32 SWD clock to ≤ 2 MHz when flashing through MUX. Keep PCB traces from MUX to pogo pins < 100mm. Use JTAG MUX IC with Ron < 5Ω (e.g. SN74CB3Q3257 or TS3USB221). Add 33Ω series termination. HW Eng
B4 Non-active Board Keeps SWDIO Floating
Un-selected PCBs may back-drive SWD lines even when not selected by MUX		 HIGH MCU SWDIO/SWDCLK pins have weak pull-ups; even with MUX tri-state, leakage through powered MCU pins can affect bus Assert NRST (hard reset) on non-active slots before MUX switches. Keep non-active slots in reset state via dedicated GPIO lines (one per slot) while their slot is not being flashed. HW + SW Eng
B5 Trace32 Connection State After MUX Switch
Trace32 loses target lock when MUX switches to a new slot — requires re-attach sequence		 HIGH Trace32 PRACTICE script maintains state for one target; switching to new PCB requires re-running SYStem.UP and memory map Write a slot_flash(n) PRACTICE wrapper that: (1) de-asserts NRST on slot n, (2) sets MUX SEL to n, (3) waits 10ms, (4) runs SYStem.RESet + SYStem.UP + flash commands, (5) asserts NRST on slot n again. Repeat for slots 1→4. SW Eng
B6 Per-Slot Power Fault Isolation
A shorted PCB in one slot must not pull down VCC for all 4 slots		 HIGH PSU output is one rail; any slot short collapses common bus voltage Add a 500mA polyfuse (PTC resettable fuse) in series with each relay output before the slot pogo pin. Monitor PSU current via SCPI; if > threshold after relay close, flag the slot as FAULT and skip it. HW Eng
B7 Flash Time × 4 Increases Cycle Time
Sequential flash = 4× single-board flash duration		 MEDIUM Only one Trace32 channel available; no true parallelism at JTAG level Optimize flash image: use blank-check skip (only write non-zero pages), increase SWD clock to max reliable speed, use Trace32 FLASH.Program AUTO (skips identical sectors). Typical flash 30s → target < 2 min total for 4 boards. SW Eng
B8 Trace32 License: Multi-Target
Some Trace32 license tiers restrict number of target connections per session		 MEDIUM License locked to specific device family or number of concurrent cores Confirm current license allows sequential disconnect/reconnect to different physical targets. Contact Lauterbach support if needed. Using one SYStem.RESet + SYStem.UP per slot (not concurrent) usually falls within standard license. Project Lead
B9 Pogo-Pin SWD Wiring in Fixture
Current fixture PCB may not route 4 independent SWD paths to a central MUX connector		 MEDIUM Original fixture design likely assumed 4 independent Trace32 probes (one per slot) or no SWD routing Fixture PCB rework: add a 5-pin header per slot (SWDIO, SWDCLK, NRST, VCC-sense, GND) that connects to the MUX board. Route NRST to a GPIO expander (PCF8574 / USB relay) under PC control. HW Eng
B10 MCU Boot Mode During Flash
Some MCUs require BOOT pins set before power-on to enter flash mode		 LOW If RH_i460 MCU requires BOOT0=1 to accept SWD flash (e.g. STM32 with option byte issue), standard power-on may boot to user code that disables SWD Verify if RH_i460 MCU SWD is accessible from user code (most ARM Cortex-M allow SWD halt override). If BOOT pins are needed, add BOOT0 control line per slot to the GPIO expander board. FW Eng
4 Hardware Solution — JTAG MUX Board Design
RECOMMENDED

Option A: Relay-Based JTAG MUX

  • Use 4× DPDT signal relays (e.g. Panasonic TQ2-5V) to route SWDIO/SWDCLK
  • PC controls relays via USB-relay board (same board already used for FCT)
  • Only one relay closed at a time per SWD line
  • Pros: galvanic isolation, no leakage, simple BOM
  • Cons: relay switching ~5ms, mechanical wear (~1M cycles)
  • Cost: ~¥3,000 for relay board
ALTERNATIVE

Option B: FTDI FT2232H Multi-Protocol MUX

  • FT2232H chip provides 2× JTAG/SWD channels independently
  • 2× FT2232H → 4 SWD channels; each maps to one slot
  • Trace32 can enumerate each FT2232H as a separate adapter
  • Pros: still sequential but avoids physical MUX; Trace32 reconnects to different USB adapter
  • Cons: requires 2× USB adapters, Trace32 config change per slot
  • Cost: ~¥8,000 for 2× FT2232H USB boards
NOT RECOMMENDED

Option C: JTAG Daisy-Chain

  • Wire all 4 MCUs in JTAG chain (TDO of board n → TDI of board n+1)
  • Trace32 sees all 4 as one long scan chain
  • Cons: SWD (2-wire) does NOT support daisy-chain (only JTAG 4-wire)
  • If MCU uses SWD only → this option is impossible
  • Even with JTAG: any unpowered board breaks the entire chain
  • Verdict: reject unless all boards are always powered + MCU supports JTAG
Recommended MUX Board Bill of Materials (Option A):
1× USB Relay board 4-channel (for power per slot) — already in BOM
1× USB Relay board 4-channel (for SWDIO/SWDCLK MUX — add to BOM)
4× 500mA PTC resettable fuse (Bourns MF-R050) — add per slot
4× 33Ω 0402 series resistors on SWDIO/SWDCLK after MUX output
1× 4-port GPIO expander (PCF8574 I2C) for NRST per slot control

6 Software Changes Required

NEW: trace32_mux_flasher.py

  • Wraps Lauterbach PRACTICE API (T32_API)
  • flash_all_slots(firmware_path) — main entry point
  • select_slot(n) — sets GPIO MUX SEL lines + NRST control
  • flash_slot(n) — SYStem.UP, FLASH.Erase, Program, Verify
  • Returns per-slot dict: {slot: PASS/FAIL, checksum}

NEW: psu_slot_controller.py

  • VISA/SCPI wrapper for KIKUSUI PWR401L
  • enable_slot(n) / disable_slot(n) via USB relay
  • enable_all_slots() for FCT phase
  • Per-slot current monitoring (fault detection)
  • OCP setting: configurable per slot via config.json

7 Implementation Roadmap
Verify RH_i460 MCU SWD accessibility — Confirm whether SWD is accessible at startup (no BOOT pin manipulation needed). Check if currently-flashed firmware disables SWD after boot. Estimated: 0.5 day.
Measure PCB current draw — Power one RH_i460 via bench PSU, measure startup and idle current. Confirm whether 1A PSU is sufficient for one board; determine total current for 4 boards in FCT phase. Estimated: 0.5 day.
Design JTAG MUX board — Select relay MUX circuit, design PCB or use off-shelf USB relay board. Add polyfuses per slot. Route SWD signals from MUX output to 4 fixture pogo-pin headers. Estimated: 3–5 days (HW Eng).
Prototype MUX wiring on bench — Before fixture PCB rework, validate MUX concept: breadboard relay MUX, connect 2 bench PCBs, manually control MUX via GPIO, verify Trace32 can flash each board sequentially. Estimated: 1 day.
Write trace32_mux_flasher.py — Implement PRACTICE API wrapper, MUX control, NRST GPIO control, flash sequence, verify, and result reporting. Unit test on 2-board bench prototype. Estimated: 2 days (SW Eng).
Write psu_slot_controller.py — Implement VISA/SCPI PSU control + relay per slot + current monitoring. Test PSU OCP and fault isolation on bench. Estimated: 1 day (SW Eng).
Fixture PCB rework — Add per-slot SWD header, NRST line, and polyfuse to fixture PCB. Run 5-pin cable from fixture to MUX board. Estimated: 2 days (HW Eng).
Integration test — 4-board flash on fixture — Full end-to-end test: robot loads 4 PCBs, software flashes all 4 sequentially, FCT runs in parallel. Verify all PASS. Estimated: 1–2 days.
Cycle-time measurement and tuning — Measure total cycle time (load + flash + FCT + unload). Optimize SWD clock, blank-check skip, parallelism. Document final throughput (PCBs/hour). Estimated: 0.5 day.
Production validation — 50-board run — Run 50 boards through automated fixture. Verify no flash failures due to MUX signal integrity. Review logs and thermal behavior of PSU under sustained load. Sign off. Estimated: 1 day.
Total Estimated Effort: ~12–14 working days (HW 5–7 days + SW 4–5 days + Integration 2–3 days)
Critical Path: JTAG MUX board design and fixture PCB rework (HW) — start these in parallel with SW development.
