--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

A Windows desktop test-bench application for U-Shin's SmartBU (XNF Handle) ECU.

Purpose:
  - Connect to a Lauterbach TRACE32 debugger attached to a PSoC 4 target board
  - Flash the target ECU with either a Non-NFC or NFC firmware variant
  - Execute functional validation tests across 9 hardware features:
    LED, Battery Monitor, Motor, EOS, Strain Gauge, Capacitive Sensor,
    NFC, CAN, LIN
  - Display live measurement values in a 12-tab Tkinter GUI panel
  - Run automated test sequences and report PASS/FAIL

Technology Stack:
  - GUI       : Python 3 Tkinter + ttk (Canvas-based layout)
  - Debugger  : Lauterbach lauterbach.trace32.rcl (RCL/UDP port 20006)
  - Target MCU: Cypress PSoC 4 (PRACTICE CMM scripts)
  - Reporting : openpyxl (Excel logs)
  - Testing   : pytest
  - Launch    : .bat scripts

2. ISSUES FOUND
--------------------------------------------------------------------------------

CRITICAL (broke at runtime):
  [1] backend_adapter package did not exist — all test suites imported from it
      Affected: comprehensive_test_executor.py, led_tests.py, motor_tests.py,
                battery_tests.py, eos_tests.py, sg_tests.py, capa_tests.py,
                nfc_tests.py, can_tests.py, lin_tests.py

  [2] orchestrator.py used wrong import paths:
        from tests.led_tests import ...        (no top-level 'tests' package)
        from tests import (battery_tests, ...) (same issue)

  [3] Functional/trace32.py hardcoded a conan2 package hash 'tracee4f08930e322b'
      for the Trace32 binary path — breaks on any machine with a different hash

  [4] LaunchTrace32() called autoexec_cmm_handler() TWICE — the second call
      overwrote the first, doubling file copy/patch operations unnecessarily

LOGIC ERRORS:
  [5] led_tests.py: tc_led_03 ("LED Not Connected") and tc_led_03_shorted
      ("Connection Shorted") used the same 2.76–3.83 V range as tc_led_01
      ("LED Connected") — a disconnected/shorted line should read ~0 V

  [6] hardware_setup.py: run_code_and_verify() polled TestFw_IsEcuSleeping
      for ANY response without checking the actual value — a sleeping ECU
      (value != 0) incorrectly passed the "running" verification

  [7] motor_tests.py / battery_tests.py: PASS criterion was only
      "value is not None" — no threshold validation applied at all

  [8] test_sequences.py: NFC and CAN results were hardcoded to False
      (placeholder stubs, never actually executed)

DESIGN / QUALITY:
  [9]  trace32_adapter.py: clear_eos_entries() and clear_sg_entries() were
       identical stubs with no meaningful distinction or documentation

  [10] Functional/logging.py: LogApp.add_log() called wb.save() on every
       single row — very inefficient for high-frequency logging

  [11] requirements.txt listed 'pathlib' — it is part of the Python standard
       library (since 3.4), not a pip package. Listing it is misleading and
       can install a conflicting legacy backport.

  [12] automation/README.md referenced stale path d:/Project/Testbench_gui_Charan
       from a different machine

      - New order:      Battery -> (early stop if 0.0 mV) -> LED ON -> LED OFF
                        -> Motor -> EOS -> SG -> CAPA
  Rationale:
    All downstream tests depend on a stable supply voltage.  A 0.0 mV
    battery reading indicates the supply or ADC has not yet initialised;
    running further tests in that state produces misleading FAIL results.

================================================================================
EXTERNAL POWER SUPPLY SETUP — OWON P4305 (for new PC / Japan colleague)
================================================================================

The OWON P4305 connects via USB and appears in Windows Device Manager as:
  "USB Test and Measurement Device (IVI)"
  under the category "USB Test and Measurement Devices"
It does NOT appear as a COM port.

Communication uses PyVISA (USBTMC transport).  The following must be installed
on any new PC before the power supply will work.

--------------------------------------------------------------------------------
STEP 1 — Install NI-VISA Runtime (required VISA backend)
--------------------------------------------------------------------------------
PyVISA on this laptop uses:  C:\windows\system32\visa32.dll  (NI-VISA)

Download NI-VISA Runtime (free, no NI license needed):
  URL:  https://www.ni.com/en/support/downloads/drivers/download.ni-visa.html
  Choose: "NI-VISA Runtime" (not the full development suite)
  Tested version: 2024 Q1 or later

After installation visa32.dll will be present and PyVISA will find it
automatically — no extra configuration needed.

  ALTERNATIVE (no NI-VISA install):
    Install pyvisa-py + libusb backend instead:
      pip install pyvisa-py pyusb
    Then install libusb-win32 or WinUSB via Zadig (https://zadig.akeo.ie/)
    and point the ResourceManager at the pure-Python backend:
      pyvisa.ResourceManager('@py')
    NOTE: The Functional/power_supply.py code uses the default ResourceManager()
    which auto-selects visa32.dll if present.  If using pyvisa-py, change
    find_owon_resource() to use ResourceManager('@py').

--------------------------------------------------------------------------------
STEP 2 — Install IVI USBTMC Driver (USB device driver)
--------------------------------------------------------------------------------
The OWON P4305 uses the IVI Foundation USBTMC device driver.

Option A (automatic — usually sufficient):
  Plug the USB cable into the PC.  Windows Update may install the driver
  automatically.  Check Device Manager:
    - GOOD: device appears under "USB Test and Measurement Devices"
            with status "This device is working properly"
    - BAD:  device appears under "Other devices" with a yellow warning icon
            → proceed to Option B

Option B (manual driver install):
  The IVI USBTMC driver is included with NI-VISA Runtime (Step 1).
  After NI-VISA is installed, unplug and re-plug the USB cable;
  Windows will find the driver automatically.

  Alternative: download the standalone IVI USBTMC driver from:
    https://www.ivifoundation.org/usbtmc

--------------------------------------------------------------------------------
STEP 3 — Install Python packages
--------------------------------------------------------------------------------
All required packages are listed in requirements.txt.  Run:

  pip install -r requirements.txt

requirements.txt includes:  pyvisa (already present)
pyserial is also in requirements.txt but is NOT used for the power supply —
it is kept only for other serial peripherals.

--------------------------------------------------------------------------------
STEP 4 — Verify detection
--------------------------------------------------------------------------------
After Steps 1-3, verify the supply is visible with:

  python -c "import pyvisa; rm = pyvisa.ResourceManager(); print(rm.list_resources())"

Expected output (serial number will differ):
  ('USB0::0x5345::0x1235::24150974::INSTR', ...)

If the USB resource appears, the power supply will be detected automatically
by find_owon_resource() — no code changes or config needed.
